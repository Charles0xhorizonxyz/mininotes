# The Android app

Native Android views and local SQLite; no WebView, no AndroidX, no XML layouts. The pad is its own Maxima node — the transport's core is vendored under `maxima-core/` and runs inside the app — so nothing else has to be installed for sharing to work, and nothing at all for the pad to work. [../docs/SHARING.md](../docs/SHARING.md) is the sharing design, [../docs/MAXIMA-TRANSPORT.md](../docs/MAXIMA-TRANSPORT.md) is how the node is carried and looked after, and what has actually been seen on a phone is in a verification log the maintainer keeps privately, build by build.

**This page is the design record of the interface, and the log is the record of what is true now.** Most of what follows was written as each piece was built and still describes it. Where it and the verification log disagree, the log is right. Three things below are history rather than description, and are marked where they stand: the Minima Core connector, the *Syncing settings* box (its job is done by **⋮ → Profile**), and the list of what was cut from the pad — search and favourites came back, as **⋮ → Search**.

It opens on a ruled note with the cursor in it. Behind that note are the shelves — collections, books, notes — one level at a time, and everything you can share is shared from the level you are looking at or the row in front of you.

As of 0.0.111, one quiet line under the open note's title says whether it is only on
this phone, synced (with the time everyone had this version) or waiting to sync.
Tap it for the exact saved and confirmed times: they are local, offline devices may
have newer edits, and attachments stay on their device.

## Build from source

Requirements: JDK 17, Android SDK platform 36 / build tools 35.0.0, Gradle 8.11.1 (wrapper), Android Gradle Plugin 8.10.1. Point `ANDROID_HOME` to the SDK, or put `sdk.dir=/your/sdk` in an untracked `local.properties`.

```sh
cd android
./gradlew testReleaseUnitTest lintRelease assembleRelease
```

Windows: `gradlew.bat testReleaseUnitTest lintRelease assembleRelease`.

The release APK is **unsigned**, under `app/build/outputs/apk/release/`, unless `android/keystore.properties` names a key — see `app/build.gradle`. No signing key is required to compile. To test locally, run `assembleDebug` or `installDebug` for an APK signed by your own development key. Android refuses to install a build over one signed with a different key, and uninstalling takes the notebook with it: export a backup first.

App ID `org.mininotes.android`, version in `app/build.gradle`, Android 9+. This initial ID must be finalized before public distribution. Retain the same signing identity for upgrades.

## Implemented and limitations

Every element on screen has to earn its place against a paper pad, which has none. What survived:

- **It opens where you left it.** A level of the shelves comes back as that level, with the way in to it; a note being written comes back as that note. The app remembering something different from where you were is the app deciding it knows better.
- **The ruled note.** A note opens ruled to the bottom, cursor at the end of the text. The keyboard stays down until you ask for it: a note you open is a note you are reading, and a keyboard covering half of it is in the way. A tap or a double tap on the page says you mean to write and brings it up; **holding a word to select and copy it does not**, because a keyboard sliding over the thing you are selecting is the opposite of helping. A blank note is the exception — there is nothing to read on one, so it opens ready to write. Writing takes no decision: no title to fill in, no formatting, no save button. Text autosaves half a second after typing stops and on leaving the screen. The rules are drawn from the text's own line height, so they fit the writing at any size rather than being a fixed pattern behind it.
- **One menu, wherever you open it.** Every `⋮` says the same things in the same order: the reading ladder, then the colour of whatever you are standing in, then what can be done to that thing (move, share, archive, delete), then what can be done with its text (send to another app), then the app itself — the same seven rows wherever you are: sync now, send to another app, how to show things, backup, syncing settings, the archive, the bin, about. A menu that changes shape from screen to screen has to be read each time; this one is learnt once. Only what cannot apply is missing: All collections has no colour or name of its own, and the archive and the bin are places rather than things, so they carry only their own one line.
- **Send to another app takes whatever you are standing in** — one note, a book's notes, a collection's books, or the whole pad — as one piece of text with a blank line between notes, in the order you put them in. The note being written on is taken from the screen, so what leaves includes the words typed a moment ago.
- **Every collection, book and note can be given a colour of its own**, from the dots in its `⋮`: eight and none. The card or row is washed with it, and an open note is written on paper of that colour — enough to recognise it across a list, not enough to fight the writing. What is stored is *which* colour, never a pixel value, so a thing keeps its colour when the paper under it changes; each colour has a strength for the light paper and one for the dark. Nothing inherits: a book's colour is the book's, and its notes stay as they are unless you say otherwise.
- **⋮ on the note** opens with the reading ladder, and under it the colours this note can be given.
- **The reading ladder: A−**, ten rungs, **A+**, and it sets the size of everything the app draws — the writing, the names under the tiles, the menu itself — because a name is as hard to read as a note when the text is too small. Each piece of text keeps its own proportion to the note's size and is scaled from it, live, without the screen being rebuilt under the finger. Each tap steps one rung and the writing behind the menu changes as you go, so the size is found by looking at the note rather than by naming it; the rules open out and close up with the text, because they are drawn from its line height. The rungs fill to where you are, the end you have reached greys out, and the size is remembered.
- **The paper is a whole set rather than a tint** — the ink, the rules, the cards, the menu and the accent are chosen for it, so the pad reads the same way light or dark. Which one is in use comes from the phone, not from a control in here. Under a line comes **Send to another app** through the Android share sheet — the share sheet already offers the clipboard, so there is no second row for it — and under another line the note itself: attach a file, move, share, archive, delete. Sending to another app is plain text leaving Mininotes through an app you choose, and is nothing to do with sharing over Minima.

**One control, one meaning.** Every screen reads the same way:

| Mark | Where | What it means |
|---|---|---|
| `←` | note, book, collection | go up one level: note → its book → its collection → all collections |
| `⋮` | the level you are in, and the open note | the same menu everywhere: what the app is set to, the colour of this thing, what can be done to it, what can be done with its text, then the app itself |
| `+` | in the list | add what this level holds |
| hold | any collection, book or note | what can be done to it comes up beside it — the same menu its `⋮` holds |
| the name itself | a collection or a book | tap it and it becomes the field it already looks like |
| hold, then move | any collection, book or note | you have picked it up: between two things to change the order, onto one of its own kind to put both in a new one |
| `A−` `A+` | every `⋮` menu | the reading size, ten rungs of it, starting in the middle |
| ● ● ● | every `⋮` menu | the colour of what you are standing in — eight plain colours and none |
| ▭▭▭ | every `⋮` menu | the tone: how loudly that colour lands, pastel to the colour itself |
| `↑` | a row or card, and the note's own line | an address has not been given this yet |
| `Shared · 2 waiting` | a tile, card or row that reaches somewhere | where it goes and whether it is up to date. Nothing at all for a thing that is only on this phone |

Rows carry nothing at all: a row is a way in, not a place to manage something. To move, share, archive or delete a collection, a book or a note, you open it and use its own `⋮`. Sharing is one item in that menu rather than a mark of its own, and the app's own items sit in the same menu under a line, so there is one mark in the bar and one place to look for anything — inside the thing itself.

At the top level there is no back control at all: nothing is above it, and the phone's own back button leaves the shelves. That returns to the note you left, not to whichever was edited last.

- **The shelves are a desktop.** Each level lays its things out across the screen the way a phone lays out its apps: a collection or a book is a bubble with the first few things inside it showing through, and a note is a small sheet of the paper it is written on, ruled like the note itself. The name sits under the square, with where the thing stands under that where it reaches somewhere — `⇄` `↗` `↙` — and `↑` beside it when an address has not been given what is inside. The archive and the bin are outlined rather than filled, because they are places rather than things.
- **Hold something and what can be done to it comes up beside it**; keep moving and you have picked it up instead. Both come out of the same press, told apart by whether the finger stayed still — which is why the menu is drawn in the app's own window rather than a popup one, so the finger that opened it still belongs to the tile underneath.
- **Two things dropped together become one that holds them both**, one level up: two notes make a book, two books make a collection, and you land inside it with the name asked for straight away, since a gesture cannot name it. Only two of a kind go together, and collections have nothing above them to make. Dropping between two things changes the order instead, and the tiles part to show where it would land. If putting them together would change who receives them, that is said by name and confirmed first, exactly as moving one thing is.
- The shelves show one level at a time. No titles and no trail: `+ New collection` / `+ New book` / `+ New note` says what a level holds, and the back arrow is the way up, one level per press, leaving the shelves only from the top.
  Tapping a collection shows its books, tapping a book shows its notes, tapping a note opens it for writing, and any step of the trail takes you back. Opening the shelves from a note starts at the book that note is in.
- **Collections and books are cards; notes are lines of text.** A thing that holds things is drawn as an object you can open — a filled card with its name and what is in it. A note is writing, so it stays a line. What is not yours to fill in — the archive, the bin, and the book something is already in while you carry it — is outlined rather than filled.
- **"+ New collection / New book / New note" sits at the top of each level**, in the list rather than in the bar, so an empty level still says what to do. That is the only place anything is added: the open note carries no **+**, because a note is for writing on, and a new one is made where notes are listed. A note nobody writes on is never stored, and an existing note emptied to nothing is removed, so the pad does not fill with blank sheets.
- **The archive and the bin are in the menu, not on the shelves.** They are places to walk into rather than things standing among your collections, so `⋮` → **Open the archive** / **Open the bin** at every level, and the boards hold only what you made.
- **A thing that reaches somewhere says so, in words.** Under its name, or at the end of its row: *Shared · up to date*, *Shared · 2 waiting*, *My devices · up to date*, *Shared with you*. A symbol has to be learnt and then remembered; a line of words is read once. A thing that is only on this phone says nothing at all — that is what everything is until it is shared, and a mark on everything marks nothing. A narrow tile takes the short of it — *Shared · 2* — and the card says it in full. Reaching another person outranks reaching your own devices, because that is the one worth noticing. What other people share with you is not kept apart in a box of its own: it stands among your own things and says on itself where it came from, which is why the bar has nothing up there for it.
- **Nothing leaves in one tap, and nothing leaves by surprise.** A collection, book or note is either on the shelves, put away in the archive, or waiting in the bin. `⋮` → **Archive** puts it away; `⋮` → **Delete** drops it in the bin. Either way it is still there and still holds whatever it held — an archived book keeps its notes, and they travel with it — so neither asks anything.
- **A thing in the archive or the bin is not a place you can walk into**, so tapping its row offers where it can go instead: **Put back**, and then **Move to the bin** or **Delete for good**. Putting something back brings back whatever holds it too, since a note put back into a binned book would be back nowhere.
- **Only what cannot be undone asks.** **Delete for good** names the thing and what goes with it — *Delete Plot 14 for good? book in My notes · 12 notes. This cannot be undone. Anything inside it goes too* — and the bin's own `⋮` holds **Empty the bin**, which says how many things that is before it does it. Deleting for good takes the sharing rules that pointed at it with it.
- **A place is not a thing.** The archive and the bin have the same menu as everywhere else, and it is short: the two ladders, then **Empty the bin** in the bin and **Nothing to put away** in the archive, then the app's own items. Neither can be renamed, coloured, moved, shared, sent, copied out or sent to another app — a bin is not something to share, and what is waiting in one is not something to send on. Put a thing back first and it is a thing again, with the whole menu.
- **`⋮` → Profile says where the chain stops.** Under **THE NODE**, four lines, each ticked or not, and the first one that is not ticked says what to do about it: this phone is its own Maxima node, it has an address, there is somebody to send to, and their keys are known. Under them, how many notes are waiting to go, and whether the pad goes on listening once it is closed. One place that knows what is missing, rather than four places explaining it differently. *(This was a box of its own called Syncing settings, which began with "Core installed" and "Mininotes enabled in Core". Neither is a step any more: nothing else has to be installed.)*
- **Nobody copies an address by hand.** The node knows its own, and the code on the Profile page carries it.
- **It goes on listening after it is closed**, once there is a device to hear from, and Android shows a notification for as long as it does. *Listens while the pad is closed* in Profile switches it off, and so does **Stop listening** on the notification. A note that arrives then is said in one line — who, and what kind of thing, never what it says — and tapping it opens that note.
- **A note written in from the other end while you have it open changes on the page**, where it stands, with anything you had typed since the last save kept. The page used to go on holding the older text, and the next word typed wrote it back over what had arrived.
- **Sharing has a direction, and every box says which.** Share is *who gets this from you*; getting somebody's notes is that same act done by them, so the box says so and points at **My address** — the thing somebody needs before anything of theirs can reach you. **Add somebody** is where your notes can go; **My address** is how notes come back. A list of names shows neither, so both are written above it.
- **Share says what somebody can do with it.** `⋮` → **Share Perso collection** — the thing and what kind of thing — heads a list of every address you know, each saying *not shared*, *reads it*, or *reads & writes*. One tap on a line moves it along: not shared → reads → reads and writes → not shared. No confirmation in the way, because the next tap puts it back. Reading means they receive what you write and cannot change it; writing means what they write comes back and is merged into yours. It is decided per share, so the same person can have one book of yours to read and another to work in.
- **The two directions are both written down.** Above the list: *I share this with*. Below it: *what somebody shares with me arrives by itself — they need my address first*. Only one of the two is yours to set, and the box says which. An address that reaches the thing through something above it says *through what holds this* and is left alone here: it is undone where it was given.
- **No address is ever typed.** Nobody types sixty characters of Maxima address correctly. **Add address** scans the other device's code or pastes what it sent; a whole pairing line goes to pairing, a bare address is simply saved. **My address** is this device's own: the address, the code for the other end to scan, and two words — **Change** to paste or scan a new one, **Copy** to put the code on the clipboard. Nothing else is on that page, because a page you hold up to another phone should not have to be scrolled to find the thing you are holding up.
- **Whose an address is, is a toggle.** In ⋮ → **Syncing settings** → the addresses line, each one carries `● mine` or `○ mine`: tap to change which way things travel — both ways with a device of yours, one way to anybody else — and hold to forget it. An address that arrives is saved as somebody else's, which is the careful way round. Nothing is shared from the top: who receives what is decided on a collection, a book or a note — the things people actually mean. What each level covers is unchanged: everything, a collection and its books, a book and its notes, or one note. It shows a count when something is shared. Addresses are saved under a name the first time you paste one and picked from the list after that; the addresses line inside Syncing settings manages them — who this phone can reach is the same subject as whether it can reach anybody, so it is not a menu row of its own. A rule set high up keeps covering what you add underneath it later. *(History: this described the Syncing settings box. Devices are now added by scanning a code from **+ → From another device** or **Shared with → Scan or paste theirs**, and what a device may do — reads, reads & writes, admin — is a chip beside its name in **Shared with**.)*
- **Nothing is renamed from a menu.** A note is named by its first line; a collection or a book is named by tapping its name where it is written — under its tile, or on its card — which turns into the field it already looks like, and tapping away keeps what is in it. The only naming box left is the one that opens by itself after two things are put together, because a gesture cannot say what the new thing is called.
- **`⋮` → About is what this is, where it came from, and where to send something.** The version goes up with every build that leaves here, so a screen can be matched to the thing that drew it; under it the source, and under that an address to donate to. Both lines are drawn whether or not there is anything to put in them yet, saying plainly that it is coming rather than quietly not existing.
- **A newer build is said, and brought here on a tap; Android does the installing.** Once a day at most, when the pad is opened or come back to, one line of text is read from the repository (`dist/latest.txt`) and compared, number by number, with what is installed. Nothing is sent with it and nothing is downloaded. If the published build is later, the pad says so in one line the first time it hears of it, and **Update to v…** stays in the `⋮` menu and in About for as long as that is true. No box is put over the page. Failing is silent and tried again at the next opening. About carries the switch that stops the daily look, under which **Check for a newer version** still looks when tapped. *(Until v0.0.107 it looked only when asked, which meant somebody who never opened About never learned that a fault had been fixed.)* Tapping the row opens a box whose one button is **Update** *(since v0.0.109; until then it opened the release page and the person did the rest)*: the pad fetches the build from the repository's release - the file the workflow named after the tag, and the checksum beside it - saying how far it has got in the strip at the foot of the window; checks that the file matches the checksum, is this app, is a later build, and is signed with the key this build was signed with; and hands it to Android's installer, which asks before installing, and the first time asks whether this app may install at all. A build signed with another key - a development build against the published one - is refused in words before Android has to, with the release page offered instead. When the new build opens it says *Updated to v…* once. What was fetched is cleared away at the next opening whatever happened.
- **Every box keeps the same room around what it says.** Words touching the edge of the thing they are written in read as if they were cut off, so a hand's width at the sides and air above and below, whether the box holds a line, a list, or a note from last Tuesday.
- **The way out is drawn largest.** The back arrow is the control most often reached for, so it is bigger than the marks beside it.
- **The shelves say whose they are.** `Mininotes` sits quietly in the bar at every shelf level, and in the same place on each: the bar is built to one measure — a place on the left for the arrow, the name in the middle, `⋮` on the right — and where there is no level above, the arrow's place is kept empty rather than closed up, so the name never moves as you go in and out. The note screen stays bare: its one line is kept for what is not saved or not sent.
- **The keyboard is one more edge of the screen.** Newer Android no longer shrinks a window for it, so the app keeps clear of it itself: whichever is deeper, the navigation bar or the keyboard, is left free at the bottom. The page is written down to that edge and no further, and a menu opened over it keeps to the room that is left, scrolling inside it rather than hiding its last items behind the keys.
- **Two devices tell each other who they are.** ⋮ → **Syncing settings** → **My address** shows this device's line — where to send and the two keys, one to seal for it and one to check what it signs — as a code to point a camera at and as text to copy. Scan or paste the other device's line and both screens show the same six digits, taken from the keys themselves: if a line was changed on its way, the digits will not agree and nobody should pair. The line is not a secret — anybody who has it can write to you and nobody who has it can read what you send — so the digits are what trust rests on.
- **The camera is only ever a way to read a code.** It opens while the scanner is showing, is looked at frame by frame for a code, and closes the moment one is found. Nothing is recorded and no frame is kept. **New address** can scan too: a code that is a whole pairing line goes to pairing, and a code that is only an address is written into the field.
- **This device's own keys** are made on first use and kept in the app's own storage, sealed under a key the phone's Keystore holds. A device may be paired with before it knows its own Minima address — the keys are what pairing is for, and where to send arrives with Core.
- **Every note keeps its history.** `⋮` → **Versions** on a note lists what it has said — when each was kept, and whether it was written here or came from an address — any of them can be read whole, and **Put this back** writes it as a new version rather than erasing what happened in between. A version is kept when an editing session ends rather than at every keystroke, so the list is a history and not a keystroke log; a hundred are kept per note, which for text is nothing.
- **Two people writing at once lose nothing.** Revisions are counted rather than timed, because two phones whose clocks disagree cannot be sorted by time without somebody's writing disappearing. What arrives is weighed against what this phone has and against the text both sides last agreed on: if it descends from what is here it is taken, if this phone has already written past it it is ignored, and if both sides wrote, the two are merged line by line. Changes in different places both land, silently. Where both wrote over the same lines, nothing is chosen for you: the page keeps what this phone was showing, what arrived is kept as a version, and the note says two versions exist.
- **A note can keep a file.** `⋮` → **Attach a file** on the note you are writing opens the system picker, and what you pick is kept with the note: name and size on a chip under the writing, tap to open it in whatever app handles it, hold to take it out. It is **copied** into the pad's own folder rather than pointed at — what another app lends you can be moved, renamed or withdrawn, and a note that loses what it held because something else tidied up is not keeping anything. 25 MB a file, and the pad says so when it is holding 500 MB altogether.
- **Files follow their note.** Archiving takes them along, deleting for good deletes them, and emptying the bin gets the room back. Bytes nobody has a row for are swept up: the row is written after the copy and deleted before it, so the one thing that can be left behind is a file nobody claims — never a name you can tap and never open.
- **Importing asks which you meant.** **Add to this pad** brings the backup's notes in beside your own as copies, reusing the shelves that are already here and making the ones that are not, so nothing lands nowhere. **Replace everything** is a restore: the pad becomes what the backup was, ids included, so the sharing rules that pointed at those things still point at them. Replacing says how much it is about to delete and cannot be undone, and it happens in one transaction — a restore that failed half way would be worse than the one it replaced.
- **A backup carries the shelves as well as what is on them** — collections and books, not only notes — because a backup of notes alone restores onto a phone with nowhere to put them.
- **A backup is a zip**, because a backup that restores the writing but not what it held is not a backup of the note: `mininotes-backup.json` and beside it the files. Import reads either kind — a backup written before files existed is that text on its own and still restores. An import adds copies, so a copied note's files are copies too, under ids of their own; importing a backup into the pad it came from leaves the originals exactly where they were. A zip is unpacked into a room of its own first, and only a plain id is taken from an entry name, so a zip cannot name a path to write to.
- **Sharing carries the writing.** A file kept with a note stays on this device: a Maxima message is size-limited, so files need splitting and reassembling, which is a protocol rather than a feature. The share sheet says so rather than letting anyone find out at the other end.
- **A web address in a note is an address.** Addresses are marked when the typing stops — underlined, in the accent colour — and tapping one opens it. Tapping anywhere else only moves the cursor, so nothing opens by accident.
- **Cards or a list.** `⋮` → **Show as a list** lays the level out one thing under another instead of across the screen, and **Show as cards** puts it back. The choice is remembered, and everything works the same way in both — holding, dragging, combining, naming.
- **One size for everything that is read.** The writing, the name under a thing's box, and every line of the menu are the same size, because they are all words you read rather than furniture — a name you cannot read is no better than writing you cannot read. The app's name in the bar is one of them — it is a word you read, so it is that size too. What is not words stays small and out of the way: the counts under a name, and the marks for where a thing stands and what is owed.
- **It opens at the ordinary size.** The middle rung is 17 point — what everything else on the phone writes in — so the app looks like the rest of the phone before anyone touches anything. Sizes are drawn in `sp`, so the phone's own text setting still moves them all; the ladder is a way to leave the ordinary size, not a thing you have to set before you can use the app. Ten rungs, 11 to 29, opening on the fifth: five either way, the steps growing as they go up because a size you can already read needs a bigger push to be noticeably bigger. The desktop follows: bigger writing means bigger tiles and fewer of them across, so a name still has room under its box, and the menu widens with its words until there is no more screen to give it.
- **What is kept is the rung, not the size.** A ladder can be re-cut; a rung means the same thing afterwards, so a pad kept in the middle stays in the middle. A size written by an older ladder is not read at all — that pad opens at the ordinary size, which is the one place worth starting from.
- **A coloured thing wears its colour at the edge.** A wash has to stay light enough to be written on, and eight light washes look like eight shades of the paper; the edge is the colour itself at full strength, so two things are told apart at a glance rather than by comparing tints.
- **Boxes are written on the app's own paper.** Every dialog takes the background, ink, accent and corner of the pad it interrupts, light or dark, and a line to write on is a box with a rule round it rather than the platform's underline — at the size everything else is read at. A box that asks for a name says what closing it does, because closing is what keeps it.
- **A colour, and how loudly it lands.** The reading ladder, then the nine colours of the thing you are standing in, then the tone. The colours are eight plain ones — red, orange, yellow, green, teal, blue, purple, pink — as far apart from each other as eight can be, so two things are never told apart by a shade. The tone says how much of that colour reaches the paper, pastel at one end and the colour itself at the other, drawn as the wash each one would actually make. Two questions, because one answer cannot be both. Everything is pointed at rather than stepped to, and the page behind the menu repaints as you go.
- **The tone belongs to the whole pad**, like the reading size: it is a matter of taste rather than of which note this is. The colour belongs to the thing.
- **Every level can be coloured, the top one included.** Standing in a collection and colouring it colours that collection; standing at the top and colouring colours the whole pad, which belongs to no collection and so is kept beside the other things the app remembers about itself.
- **The room shows the colour of what you are standing in.** You cannot see a thing's own tile from inside it, so the level itself takes the wash — colour a book from inside it and the book's room changes under the menu.
- **Light or dark is the phone's setting, not ours.** The app is written on a light paper when the phone is light and a dark one when it is dark, and follows the moment that changes — the way every other app decides it. The ten-paper scale of greys is gone: it was a choice nobody wants to make twice, and it sat in front of the one choice that is actually about this pad. The other papers remain in the source as what those two are cut from.
- **A note is named by writing it.** The first line of a note is its name — on its tile, in the archive, in a backup — so the note says so itself: an empty one reads *Write. The first line is its name.*, and once there is one it is drawn bold. Bold rather than bigger, because a taller line would outgrow the rule it sits on. There is no Rename for a note, and nothing else names one: a second way to set the same line is a second thing to keep in step. Collections and books, which have no first line, are renamed from their own menu.
- **Press and hold anything to drag it into the order you want.** The line lifts, leaves its gap behind, and the gap follows your finger through the level; let go and that is the order, kept and written silently. Held against the top or bottom of a long list, it scrolls. Let go anywhere but the list and nothing moved. Collections, books and notes all order this way, and each level has its own order. Holding means only this — a line opens on a tap and moves on a hold — while moving something into a *different* book or collection stays in `⋮` → **Move somewhere else**, where what it would change is checked first.
- **A level keeps the order you gave it.** Until something is dragged, a level reads newest first, and anything new — a note, a book, a collection — arrives at the top, which is where you are looking for it. Once you have dragged, that order is what stands: writing on an old note no longer pulls it back up the list, because the list is yours now. Something moved into another book or collection also lands at the top of it.
- **Move somewhere else** turns the screen into the places that thing can go — every book when carrying a note, every collection when carrying a book — and you tap one; the book it is already in is shown greyed as "where it is now". A note can also be deleted from there, which is the only place a note is deleted from.
- **A move that changes who can read something has to be confirmed.** Before anything is written the app works out the audience the note would gain and lose, and says so by name: *Moving "Ideas for the allotment" into Reading changes who receives it. Starts reaching: Ana (someone else).* A move that changes nobody just happens.
- **Nothing is confirmed and nothing is cancelled.** A box closes by tapping outside it, and closing is what saves it: type a name and close, and the thing is named; close without typing and nothing happens. The only buttons left are ones that *do* something — Add address, Delete, Move anyway, Check Core — never OK, Cancel, Done or Close.
- **A single warning line**, only when a save fails; tapping it retries. When the save is fine but an address has not been given the note as it stands, the same line says so quietly — *Not sent yet*, or *Not sent to 2 addresses*. Silence means saved, and given to whoever receives it.
- **`↑` marks anything an address is behind on**: on a note's row, and on the book and collection holding it, with a count of how many notes inside are waiting. A note counts once however many addresses are owed it, because the mark says *this is behind*, not how many deliveries that is. Write one more word on a note that had reached everybody and the mark comes back, which is the whole point of it.
- **`⋮` → Sync now** says what that thing owes and to whom, by name, and sends it. Most of the time nobody needs it: what the open note owes goes by itself once the writing has stopped for as long as that thing asks for, and everything owed goes when the pad opens. **Only a delivery clears a mark** — and a delivery, today, means a relay took the message, which is less than it sounds. See *Not built* in [the sharing design](../docs/SHARING.md).
- **The menu is drawn by the app, not taken from the platform**, so that the reading ladder can live in it: a platform menu row can only be tapped once and dismissed, and stepping a size means staying open and watching the note. It is the same sheet in both bars — rows of words, thin lines between the groups — so the two menus stay one thing.
- **Backup and Syncing settings**, behind the list's ⋮. Backup is one row holding both writing one out and reading one back in — the same subject, asked about twice a year. It exists because app storage is the only copy and uninstalling deletes it. Syncing settings exists because carrying the same pad between your own machines over Minima is the point of the project.

Removed as unjustified for a pad: the title field, the separate notebook field, the trash view, and every screen heading and tagline. Pins and the search box were on that list too and came back once there was enough on the shelves to lose things in — as **⋮ → Search**, which opens on *Kept to hand* and *Lately* before anything is typed, and **The whole tree** beside it. `title`, `notebook` and `deleted` remain in the database and the backup format so existing backups still load; an imported note keeps its title as the note's first line.

Collections and books are the exception to that pruning, and sharing is their justification: you share at the level you organise at, so the levels have to exist. Writing is unaffected — the app still opens on the note you last wrote, wherever it lives, and a first run has one collection holding one book so nothing must be chosen before writing.
- **Three workers, each serialized.** The notebook's, so that a read always observes the writes queued before it and a result for a screen the reader has left is dropped instead of drawn. One for whatever waits on the network and somebody is waiting for — sending, pairing, asking the node for its address. And one for the housekeeping a node wants when it has just come up, which nobody is waiting for. They were one worker for a long time: a word typed waited to be saved behind a note being sent, and leaving the app stalled for two seconds waiting on a relay.
- A note row reads a 280-character preview rather than the whole note; the whole note is read only when it is opened. The store refuses to write a partially read row back over a stored note, so a preview can never truncate the original.
- The schema is versioned with ordered, additive migration steps — version 17 at the time of writing, and `SchemaMigrations` is the list: each step says what it added and why, and each has a test. A step is never edited after it has shipped. A failed step leaves the previous schema and notes intact, and a database written by a newer build is refused rather than rewritten.
- JSON import/export through Android's document picker, compatible with the initial MiniDapp format. Import is transactional and creates new IDs. No migration silently moves browser data.
- *(History.)* `CoreConnection` is a source-built connector to a separately installed Minima Core: explicit package target, random pairing and request ids, response token checks, bounds and timeouts, and only registration and the read-only `status` command. It was built when Core was expected to carry the post. Core's build turned out to have no Maxima in it, the pad became its own node instead, and nothing in sharing touches this any more.
- The sealed-note format for sharing: ephemeral P-256 ECDH, HKDF-SHA256, AES-256-GCM and an ECDSA signature, so a relaying node carries a note it cannot read or alter undetected. It proves a message is intact, not who sent it; matching the sender's fingerprint to a paired device is the caller's job. See [the sharing design](../docs/SHARING.md).
- Unit tests for everything that can be decided without a device, each in a class with no Android types in it: causal revision ordering, the merge, what to do with an arriving note and with the page that is open when it arrives, who is a member of what and which of two decisions stands, what travels in a parcel, what each address is still owed, the sealed-note format, the pairing line and the short form of a key, QR drawing and reading, SHA3, schema version rules, the workers' ordering, failure, flush and shutdown, search, where a dragged line lands, how a colour is laid over a surface, attachments, and the feedback form.

Notes are stored **unencrypted** in the app's private SQLite database; what is shared is sealed end to end, what stays is not. App lock and an encrypted vault remain planned. Saving is asynchronous: `onPause` and `onSaveInstanceState` wait up to two seconds for queued writes to reach disk, so a process killed during a slower write can still lose the last edit. A save that fails while the note is open is shown and can be retried; one that fails after the note was closed reopens it with the text so it can be retried, unless a different note was opened first, in which case the app says the edit was not stored rather than replacing what is on screen.

What has been exercised, on which phone and on which build — including, every time, what was *not* seen — is written down before each release in a log the maintainer keeps privately, because it names their phones and quotes their notes. Nothing should be believed about a device on the strength of the code alone; ask in an issue for the log's entry for a build.

## The Minima Core connector (history)

The adapter is an original implementation of the public upstream contract; no binary AAR is bundled. Its identifier strings are based on the Apache-2.0 upstream source pinned in `../docs/research/core-upstream-commit.txt`. The upstream token protocol authenticates the peer holding the pairing token; it is not Android certificate pinning. Initial registration trusts the installed application at the explicit Core package. Nothing that arrives through it is allowed to edit the notebook, and nothing in sharing goes through it: notes arrive through the pad's own node, sealed, from a device whose signing key was paired with, and from nobody else.

This app never requests Admin or grants permissions in Core. Pairing tokens, addresses, keys and note content must not enter logs or OS cloud/device-transfer backup — the log lines the node and the post write are counts and outcomes only. Explicit note backups remain available through the document picker.
